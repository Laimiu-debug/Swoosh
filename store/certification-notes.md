# Microsoft Store 审核员说明草稿

以下说明在正式提交时粘贴到「认证说明」。包身份、版本、截图和实机检查完成后再提交，不把开发包上传到正式产品。

## 操作步骤

1. 在两台 Windows x64 电脑上安装相同待审核版本，连接同一允许设备互通的局域网。
2. 启动两端 Swoosh。无需应用账号、测试账号或互联网文件中转服务。
3. 在发送端选择一个文件、一个文件夹，或切换到文字页输入测试文字。
4. 选取对方设备。如果没有自动发现，打开「连接设备」，用另一端显示的局域网 IP 和端口手动连接。
5. 两端都会显示六位短码。核对相同后，两端分别确认，传输才会开始；60 秒未完成确认会过期。
6. 文件在接收端的系统「下载 / Swoosh」目录下，按本次传输建立独立文件夹。点击「打开收到的文件」或历史中的文件夹按钮检查结果。文字在当次传输卡片显示，点击「复制文字」检查剪贴板。
7. 重复发送相同文件，应建立新的接收目录，已有内容不被覆盖。取消或拒绝后不会发布未完成的文件。

## 权限用途

- `runFullTrust`：Tauri Win32 桌面应用需要以当前用户运行 Rust 文件处理、TLS 监听、mDNS 发现、原生选择对话框、剪贴板写入及打开接收目录。应用不请求管理员权限，不安装系统服务。
- 网络能力：发现并连接同一可互通局域网的设备。文件内容直接传到用户选定的接收端。
- 声明式防火墙规则：仅针对本包 `swoosh.exe` 和专用网络；UDP 5353 用于 mDNS，TCP 用于 TLS 接收。默认监听 53318，端口被占用时改用可用端口，因此 TCP 规则未固定单一端口。未声明公共网络例外。
- 文件访问：原生对话框或拖放选择用户主动发送的内容；接收写入系统下载目录。未申请 `broadFileSystemAccess`。
- 剪贴板：只有点击「复制文字」才写入；不做持续监听或同步。

本地设备身份与元数据历史保存在应用数据目录；历史不保存文字正文。隐私政策：https://swoosh-laimiu.laimiu-new.chatgpt.site/privacy.html

## 当前不能承诺的能力

仅 Windows 桌面 x64。没有手机端、扫码、后台服务、自动接收、断点续传或 LocalSend 协议兼容。关闭应用后不能继续接收。

## 提交前必须确认

Microsoft Edge WebView2 Runtime 在干净机器上的安装/存在策略仍需验收。当前 MSIX 使用系统 Evergreen Runtime；它不包含 NSIS 的运行环境安装步骤，不能把 NSIS 的补装能力当作 MSIX 已有能力。没有 WebView2 的设备须先补装运行环境；若干净机器验收要求完全自包含，应在正式包中实现并测试微软 Fixed Version Runtime 方案。
