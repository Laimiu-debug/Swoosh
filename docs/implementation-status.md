# Swoosh 开发进度

更新日期：2026 年 10 月 6 日。阶段：Windows 技术验证。

## 已实现

应用采用 Tauri 2 独立窗口，发布资源内嵌在程序中。React 界面展示真实状态，Rust 核心负责网络、文件内容、身份与历史。原生对话框可选择文件或文件夹，桌面拖放可导入路径；前端不读取或搬运文件字节。

设备通过 mDNS 自动发现，也可输入另一端的局域网 IP 与端口。接收端使用 rustls TLS；连接后固定证书 SHA-256 指纹，不跟随重定向、不使用系统 HTTP 代理、不访问公网地址。首次连接只读取设备信息，发现结果没有接收权限。

发送请求由 Ed25519 设备密钥签名。短码由完整清单、两端身份和一次性随机 nonce 派生，双方确认同一码后才开始传输。短码不是设备定位码。确认请求 60 秒内有效，每次发送都需要确认；没有假装实现「记住设备」或免确认。

文件流顺序上传，接收端逐文件校验大小与 SHA-256。清单限制 10000 项，拒绝路径穿越、Windows 保留文件名、同名路径冲突与符号链接。未完成内容保存在本次会话的临时目录，全部成功后发布为独立接收文件夹。纯文本限制 1 MiB，只在当次界面中显示；SQLite 历史保存元数据，不保存正文。

## 验证

已成功构建 Windows x64 EXE（约 17.3 MiB）与 NSIS 安装程序（约 4.7 MiB），前端类型检查、设计资源检查、rustfmt 与 Clippy 无警告检查通过。实际桌面窗口已启动，并显示本机设备信息。首次运行的 Windows 网络权限弹窗需要用户处理；原生选择与界面发送操作的人工验证暂待弹窗处理。安装包构建成功，不代表已完成安装与卸载验收。

品牌图标已更新为 0.4「小信使」。重新构建后确认程序与安装器均嵌入六档新图标，并提取 Windows 实际读取的图标检查。构建脚本显式跟踪图标目录变化，避免仅修改 ICO 时沿用旧的 Windows 编译资源；安装器与卸载器均指定品牌 ICO。

自动测试建立两个独立身份和接收目录，通过实际 HTTPS 请求完成发送与接收，覆盖：

- 两端确认缺一不可；中文、Emoji 与换行保持一致。
- 中文目录、空文件、空文件夹和 2 MiB 文件完整传输。
- 重复发送到独立目录，已有内容不覆盖。
- 取消和拒绝停止传输；源文件发生变化时校验失败并清理临时内容。
- 无授权上传、错误会话令牌、重复 nonce、清单篡改和错误证书指纹被拒绝。
- 设备身份与历史在重新启动后保留，清空历史不删除收到的文件。

同机网络测试不能证明不同路由器、网卡与防火墙环境下的发现成功率或传输性能。后续必须在两台 Windows 电脑上验证 mDNS、专用网络授权、实际大文件、网络中断和应用退出，再扩展 Android。

开发时可运行 `cargo run -p swoosh-core --example loopback_receiver -- .local/loopback-receiver`，用真实 TLS 接收端检查桌面发送流程。这个测试实例只绑定 `127.0.0.1`，会自动批准测试请求，10 分钟后退出，不包含在应用或安装包中。应用的正常局域网接收始终需要两端确认。

## Microsoft Store 准备

已加入 Windows SDK MakeAppx 打包流程，使用 Tauri release EXE 生成未签名 MSIX；本次清单 schema 验证、资源打包和解包后 EXE SHA-256 对比通过。已生成本地开发身份 `Swoosh.LocalPreview` 的 1.0.0.0 包，当前应用版本仍为 0.1.0，不能将开发身份包提交商店。

已准备中文商店文案、300px 列表图标及包内多尺度图标、审核流程与权限说明，并补充官网隐私政策。用户尚未注册开发者账号，待实名、产品名称预留及实际包身份。正式收费前还需 MSIX 安装/升级/卸载、干净机器 WebView2、Windows App Certification Kit 与真实双机验收。本次桌面操作被用户通过 Esc 停止，未继续 UI 操作或生成实拍截图，官网示意图不会作为商店截图使用。完整材料见 `store/README.md`。

## 尚未交付

Android 与 iOS、二维码、可信设备存储、自动接收、接收目录设置、重试队列、速度与剩余时间估算、断点续传、后台服务、系统分享与右键菜单。当前协议为 Swoosh 自有协议，不声明 LocalSend 兼容。默认最多同时处理 4 个发送会话和 4 个接收会话。

发布前还需审查身份存储权限、协议资源限制、短码用户流程、TLS 指纹策略与平台差异；当前代码属于开发验证版本。
